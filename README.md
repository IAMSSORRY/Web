# IAMSSORRY — 암쏘사과

> 판정 근거를 제시하는 사과 선별 시스템

PAC 2026 Physical AI Challenge · 분과① 로보틱스 미션 · 안동청과 기업문제 해결

---

## 무엇을 하는가

사과 5개가 놓인 트레이에서 로봇팔이 사과를 하나씩 집어 색으로 등급(상/중)을 판별하고 해당 상자에 적재합니다.

이 시스템의 초점은 속도가 아니라 **신뢰**입니다. 기계가 등급을 매겨도 판정 근거를 제시하지 못하면 현장은 결국 사람이 다시 검수하게 되고, 자동화의 이득이 사라집니다. 그래서 판정에 쓰인 색상값, 임계값, 신뢰도를 실시간으로 함께 보여줍니다.

### 설계 원칙

**조건을 물리적으로 고정한다**
트레이 위에서 바로 색을 판별하지 않습니다. 사과마다 카메라와의 거리·각도·조명이 다르면 같은 사과도 다른 색으로 측정됩니다. 로봇팔이 사과를 파지한 뒤 조명이 통제된 고정 검사 위치로 옮겨 판별하므로, 모든 사과가 동일한 조건에서 평가됩니다.

**근거를 함께 제시한다**
등급만 내놓지 않고 그 판단에 쓰인 수치를 같이 표시합니다. 판정 과정이 보여야 사람이 확인할 수 있고, 확인할 수 있어야 맡길 수 있습니다.

**실패를 스스로 인지한다**
적재 직후 영상 차분으로 사과의 굴림을 감지하고, 발생 시 다음 동작의 접근 속도와 적재 높이를 자동으로 낮춥니다.

## 기술 스택

| 영역 | 스택 |
|---|---|
| 빌드 | Vite |
| 프레임워크 | React 18 + TypeScript |
| 스타일 | Tailwind CSS |
| 차트 | Recharts |
| 통신 | 네이티브 WebSocket |

Next.js가 아닌 Vite를 쓴 이유는 로컬 네트워크 전용 실시간 모니터링 화면이라 SSR·라우팅·SEO가 불필요하고, 개발 서버 리로드 속도가 짧은 개발 기간에 실질적인 차이를 만들기 때문입니다.

## 실행

```bash
npm install
npm run dev
```

기본 포트는 `5173`입니다.

### 환경 변수

`.env.local` 파일을 만들고 로봇 제어 머신의 WebSocket 주소를 지정합니다.

```
VITE_WS_URL=ws://192.168.0.10:8765
```

주소를 지정하지 않으면 더미 데이터 모드로 동작합니다. 로봇 없이 UI를 개발할 때 사용합니다.

## 데이터 형식

비전 파이프라인에서 WebSocket으로 아래 형태의 JSON을 수신합니다.

```json
{
  "frame": "<base64 JPEG>",
  "apples": [
    {
      "id": 1,
      "bbox": [120, 84, 96, 96],
      "grade": "상",
      "confidence": 0.87,
      "v_value": 182
    }
  ],
  "stats": { "상": 3, "중": 2, "total": 5 },
  "motion": { "approach_speed": 0.8, "roll_detected": false },
  "cycle_time": 4.2
}
```

- `frame` — 송출용 축소 프레임. 판별은 원본 해상도로 수행되며 여기에는 축소본만 실립니다
- `v_value` — HSV 색공간의 명도값. 등급 판정의 근거 수치
- `confidence` — 판정 신뢰도. 낮을 경우 로봇이 각도를 바꿔 추가 검사를 수행합니다

## 시스템 구성

```
[ ASUS 리눅스 노트북 ]              [ 맥북 ]
  ROS2 Humble                        Vite dev server
  PIPER 로봇팔 제어 (CAN)      ←→    대시보드 (브라우저)
```
